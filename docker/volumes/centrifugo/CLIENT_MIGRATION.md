# Migrating from Supabase Realtime

This guide is for applications moving a feature from Supabase Realtime to the Centrifugo beta. Use the official Centrifugo SDK for the platform. The files under `examples/` are reference integrations, not a separate published SDK.

## 1. Install the official client

| Platform | Official SDK | Install |
| --- | --- | --- |
| JavaScript/TypeScript | `centrifuge-js` | `npm install centrifuge@5.8.0` |
| Kotlin/Android/Java | `centrifuge-java` | `implementation("io.github.centrifugal:centrifuge-java:0.8.0")` |
| Swift/iOS | `centrifuge-swift` | Swift Package Manager: `https://github.com/centrifugal/centrifuge-swift.git` |
| Flutter/Dart | `centrifuge-dart` | `flutter pub add centrifuge` |
| Python | `centrifuge-python` | `pip install centrifuge-python` |
| Go | `centrifuge-go` | `go get github.com/centrifugal/centrifuge-go` |

The JS and Kotlin versions above are the ones exercised by the conformance tests. Pin the other SDKs to versions your application tests.

Do not copy the Phoenix protocol or use a Supabase Realtime client against Centrifugo. The JS and Kotlin conformance runners in this repository show the token callback, channel names, reconnect handling, and duplicate suppression expected by this beta.

## 2. Change the base URL

Supabase Realtime:

```text
wss://PROJECT.supabase.co/realtime/v1/websocket?apikey=...&vsn=1.0.0
```

Centrifugo beta:

```text
wss://PROJECT.supabase.co/realtime/v1/connection/websocket
wss://PROJECT.supabase.co/centrifugo/v1/connection/websocket
```

Both Centrifugo paths are equivalent. `/realtime/v1/websocket` remains Supabase Realtime and is not part of this migration.

Remove `apikey` and `vsn` from the WebSocket query string. The API key moves to the token request only. Do not put the service-role key or Centrifugo API key in a client.

## 3. Replace Realtime auth with a token callback

Old Supabase Realtime flow:

```js
const client = createClient(SUPABASE_URL, SUPABASE_ANON_KEY)
const channel = client.channel('room:1')
await client.realtime.setAuth()
channel.subscribe()
```

Centrifugo flow:

```js
import { Centrifuge, UnauthorizedError } from 'centrifuge'

const client = new Centrifuge(
  'wss://PROJECT.supabase.co/realtime/v1/connection/websocket',
  {
    getToken: async () => {
      const response = await fetch(
        'https://PROJECT.supabase.co/centrifugo/v1/auth/token',
        {
          method: 'POST',
          headers: {
            apikey: SUPABASE_ANON_KEY,
            authorization: `Bearer ${await getSupabaseAccessToken()}`,
          },
        }
      )
      if (!response.ok) {
        const retryable = response.status === 429 || response.status >= 500
        if (!retryable) throw new UnauthorizedError('Centrifugo token request failed')
        throw new Error(`Centrifugo token request failed (${response.status})`)
      }
      return (await response.json()).token
    },
  }
)
```

Rules:

- Send the publishable/anon key in `apikey`.
- Send the current Supabase access token as `Authorization: Bearer ...` for a user connection.
- Omit the bearer token only for anonymous access to `public:*`.
- Call `getToken` again when the SDK asks; do not cache a token past its expiry.
- Treat `401`, `403`, `invalid_apikey`, and `service_key_not_allowed` as terminal. Treat `429` and `5xx` as retryable.
- Never log the access token or Centrifugo token.

## 4. Map channel names

Supabase channel names are application-defined; Centrifugo names are validated and namespaced. There is no automatic translation.

| Supabase Realtime topic | Centrifugo channel | Notes |
| --- | --- | --- |
| `room:1` | `public:room-1` | Public channels cannot contain `:`. |
| `room:1` (tenant-private) | `tenant:<tenant_uuid>:room:1` | At most four segments after the tenant UUID; each starts with a letter or digit. |
| `private:user:<uuid>` | `user:<uuid>` | The user can only subscribe to their own UUID. |
| `postgres_changes` for `messages` | `tenant:<tenant_uuid>:table:messages` | Generated by `centrifugo.broadcast_changes_trigger`. |
| Dynamic topic with a UUID | `tenant:<tenant_uuid>:<your-segment>` | Validate the UUID before building the name. |

Keep the Supabase topic as an application-level mapping key if existing clients and server code depend on it. Do not pass user input directly into a channel name.

## 5. Replace channel methods

| Supabase Realtime | Centrifugo |
| --- | --- |
| `client.channel(topic)` | `client.newSubscription(channel)` |
| `channel.subscribe()` | `subscription.subscribe()` |
| `channel.unsubscribe()` | `subscription.unsubscribe()` |
| `channel.send({ type, event, payload })` | `subscription.publish(data)` where client publish is enabled; otherwise `POST /centrifugo/v1/api/publish` from the server |
| `channel.presenceState()` | `subscription.presence()` for a snapshot; use `join`/`leave` for changes |
| `postgres_changes` callback | `publication` callback with the outbox payload |
| `system` callback | Client `connected`, `disconnected`, `error`; subscription `subscribed`, `unsubscribed`, `error` |
| `channel.track(state)` | Not supported; use auth service connection/subscription metadata |

When client publish is enabled, the data value must be a JSON object and is limited to 16 KiB. The server API is the preferred path for trusted broadcasts and bypasses client rate limits.

## 6. Event mapping

### Broadcast

Supabase sends a wrapper containing `type`, `event`, and `payload`. Centrifugo sends the `data` value directly. Put the event name inside the data if the application needs it:

```json
{ "type": "broadcast", "event": "cursor", "payload": { "x": 1 } }
```

becomes:

```json
{ "event": "cursor", "payload": { "x": 1 } }
```

### Postgres changes

Notification-only outbox payload:

```json
{
  "event": "insert",
  "schema": "public",
  "table": "messages",
  "tenant_id": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
  "occurred_at": "2026-11-03T12:00:00.000Z",
  "message_id": "bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbbb"
}
```

Full-row tables add `record`; updates may add `old_record`. There is no WAL CDC and no exact RLS row filtering. Treat the payload as a notification and reload authoritative state when it is incomplete.

### Presence

`presence()` returns a map of client IDs to client info. There is no Supabase-style per-client `track` state and no presence diff array. Use join/leave for changes and reload presence after reconnect.

## 7. Reconnect, recovery, and duplicates

- Let the official SDK reconnect and refresh tokens. Do not add a parallel reconnect loop.
- Enable `recoverable` and `positioned` subscriptions.
- On `subscribed`, check `recovered`. If it is `false`, or the server returns `112`, reload authoritative state.
- Deduplicate by `data.message_id` when present, otherwise by publication `offset`. Keep a bounded set; the examples use a 2048-entry, 10-minute deduplicator.
- Redis restart invalidates subscription state and sends `unsubscribe` code `2500`. The SDK resubscribes and recovers; if history is unavailable, reload state.
- History is a bounded cache (100 publications, 300 seconds by default), not a durable event log.
- Mobile apps should disconnect on background and connect on foreground; close the client when the screen or session is destroyed.

## 8. Unsupported behavior

The following Supabase Realtime behavior is not translated:

- Phoenix protocol frames or `vsn=1.0.0`.
- `channel.track(state)` and `untrack()` arbitrary presence state.
- `postgres_changes` server-side equality/in filters; filter locally after delivery.
- WAL-level change capture, old-record replay, and exact RLS row filtering.
- Automatic translation of `private:` or existing topic names.
- Supabase `system` event payload parity.
- Multi-node presence/history without the scale overlay; production Redis HA is environment-dependent.

## 9. Rollback to Supabase Realtime

Keep Supabase Realtime deployed and `/realtime/v1/websocket` unchanged during the beta. To roll back:

1. Disable the client feature flag that selects the Centrifugo SDK.
2. Restore the previous Supabase channel names and event handlers.
3. Stop writing new feature traffic to the Centrifugo channels.
4. Leave `/centrifugo/v1/*` routes in place until all clients have moved; they do not affect Supabase Realtime.
5. Recreate presence/state from the application database after switching back. Centrifugo history is not a recovery source.

Do not run both clients for the same feature without deduplicating at the application layer. If dual delivery is required during the transition, use the outbox `message_id` as the idempotency key.
